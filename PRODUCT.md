# semverge

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers and maintainers who ship and operate software. The foundation supports
one authenticated operator workspace; the ambition is a commercially hosted and
self-hosted platform for teams.

## Product Purpose

Help developers ship, monitor, maintain and recover software by connecting what
changed, what was affected and what action is supported by evidence.

## Positioning

Evolve the existing deterministic release engine into a cohesive reliability and
operations platform. Release intent, readiness and publication evidence contribute
context to operational signals and incident response. Correlation is not causation.

## Operating Context

Existing GitHub Action and local CLI remain the release authority. The separate
web runtime uses a persistent catalog, real HTTP observations, imported release
transactions and an incident timeline. It must work without paid infrastructure.

## Capabilities and Constraints

The foundation's four connected areas are Overview, Releases, Monitoring and
Incidents. Future product areas are Errors, Maintenance and Recovery. Do not
present them as implemented. No fake metrics, decorative dashboards, automatic
production deployments, payments or artificial commercial restrictions.

Preserve existing release functionality and compatibility. Avoid premature
distributed systems and expensive enterprise architecture. A complete,
demonstrable milestone takes precedence over a shallow implementation of the
entire roadmap. Runtime and implementation details live in `platform/README.md`.

## Brand Commitments

Name: semverge. The primary direct brand reference is the user's monochrome
Sero board (`IMG_7295.PNG`): near-black fields, silver/white directional light,
light sans-serif lettering and sculptural repeated forms. Earlier references
included electric blue; the direct monochrome reference now leads. Interpret
the references as inspiration; do not copy their logos or
marketing claims. The user requires the quality and care of Linear, Vercel and
Stripe, a cohesive product, and no generic AI-generated SaaS aesthetic.

## Evidence on Hand

Actual release engine and tests; recorded transaction schemas; a tested platform
API and worker with real HTTP failure/recovery tests. No customer testimonials,
adoption metrics, uptime claims, global probes, error SDK or hosted production
service are established. A demonstration must be explicitly identified and use
actual observations rather than invented history.

## Product Principles

- Keep deterministic release decisions and publication authority intact.
- Make service/environment context explicit across every product area.
- Give every control a working, evidence-backed behavior.
- Keep unknown and stale states visible.
- Earn open-source trust through inspectable code, tests and honest boundaries.

## Accessibility & Inclusion

Keyboard-operable forms and navigation, readable status labels beyond color,
responsive layouts, visible focus, and reduced-motion support.
