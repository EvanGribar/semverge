One understandable workflow

Every release has a story you can inspect.

  1. 01Plan

    Read commits, pull requests, labels, and package relationships.

  2. 02Explain

    Show the version decision, readiness blockers, and dependency graph.

  3. 03Publish

    Build first, then record idempotent package, tag, release, and asset effects.

  4. 04Verify

    Check the published release and keep a safe next action for recovery.
