# Commit-bound release evidence v1

The SemVerge evidence workflow checks out the exact GitHub event commit, runs the repository's verification suite, and validates SemVerge configuration with the CLI. The team workspace and the hosted MCP `release_status` response read the same evidence adapter. Cloud does not clone, build, or run repository code. Send `commit` (a full lowercase SHA) with `release_status` when a decision depends on a specific release branch head.

The versioned record includes the GitHub repository ID and name, branch, source SHA, workflow and `.semverge.yml` blob revisions, evaluation time, workflow run and attempt, result, and explanation. Evidence comes directly from GitHub's repository, Actions run, and job APIs. The adapter accepts a reviewed workflow revision, requires matching run and job identity, and checks the branch head and run attempt again before returning. Missing, mismatched, malformed, pending, or more than seven days old evidence is unavailable. Failed checks stay failed, with a link to the run for details.

This first producer is for SemVerge's own repository layout and verification commands. It verifies the repository suite and configuration; it does not produce a version plan, evaluate PR labels, authorize publication, or attest to built artifacts. The trust boundary includes GitHub Actions and the maintainers of the configured release branch, whose code runs in that workflow. The Git blob IDs identify policy revisions; GitHub's live API provides origin information. There is no portable signed attestation in v1. PR plan readiness and published release reports are separate evidence.

For private repositories, approve **Actions: Read** on the GitHub App installation. Cloud requests that permission on a separate token limited to the connected repository. The evidence is unavailable if this permission is absent; other release views can still load. The producer runs on branch pushes and can be dispatched by a repository operator on the release branch once installed on the default branch. A branch update made with GitHub's built-in workflow token may not trigger the push workflow; the result remains unavailable until the evidence workflow runs for that SHA.

Provider reference: [GitHub Actions workflow runs](https://docs.github.com/en/rest/actions/workflow-runs) and [jobs](https://docs.github.com/en/rest/actions/workflow-jobs).
