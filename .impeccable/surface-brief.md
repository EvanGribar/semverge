# Platform workspace

Target: `platform/web/index.html`, `platform/web/app.js`, `platform/web/styles.css`.
Mode: Operate. Code-first, then rendered desktop/mobile verification.
User-confirmed job: operate a real web product with Overview, Releases, Monitoring
and Incidents, rather than a local file viewer or an expensive enterprise SaaS.

## Direction contract

THESIS: One operational workspace joins the service catalog, release evidence,
real checks and incident timelines. The main content is actionable records, not a
hero and a grid of performance numbers.

OWN-WORLD: Graphite and near-black, silver text and off-white actions,
precise sans-serif labels and measured line icons. A bespoke converging-ribbon
mark is distinct from the inspiration logos. Status always has a word.

STORY: Sign in, establish a service/environment, add a real check, investigate its
history, acknowledge an incident, associate release evidence and see recovery.

FIRST VIEWPORT: A compact left navigation rail, quiet context bar, clear Overview
heading and environment scope, an observation summary, and a wide application
ledger. Recent releases and active incidents continue below. Empty installations
show an actual creation form rather than sample telemetry. Signature interaction:
one service/environment context stays legible from check history to incident
timeline and explicitly linked release evidence.

FORM: Candidate 3, operator's service ledger, seed f7fceddb. The grounded field:
1 production change log; 2 source-control workbench; 3 operator's service ledger;
4 build trace; 5 incident notebook; 6 deployment manifest; 7 diagnostic report.
The user's direct Sero reference pins the dark/silver monochrome world. Transit is competitive in context
preservation; timetable and ticket-wallet lose clarity but donate fixed status
cells and durable history. Bitmap and mascot catalogs lose audience identification
and clarity; donate disciplined repetition and individually named entities, not
their visual costumes. Emission-line rail is competitive in state legibility;
retain explicit unknown/paused labels without importing its single-size layout.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish
review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Constraints

No seeded customer data, fake metrics or future-feature navigation. Root website,
release semantics and Action remain intact. No external fonts/assets, billing or
deployment. Forms are inline; browser state comes from the authenticated API.
Runtime: Node 24.13.0 and SQLite, one operator workspace.

## Confirmed Unslop polish direction

The user approved a focused polish pass, then identified the monochrome Sero
board as direct brand inspiration. Preserve structure and functional scope;
use the updated monochrome world, readable metadata, regular spacing and direct
mobile visibility of service status. Product: software release and operations
workspace for developers. Character: calm, exact, accountable. World: operational
instruments and change records. Moments: real observations and incident timelines.
Signature: persistent service, environment and release context.
